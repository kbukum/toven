# Initialize a repository

`toven init` detects supported ecosystems and creates or extends `toven.toml`.

```bash
toven init --print
```

## Syntax

```text
toven init [--root <PATH>] [--force <ID>] [--non-interactive] [--print]
```

## Write `toven.toml`

```bash
toven init
```

On a terminal, Toven asks ecosystem-specific questions and previews the configuration before writing it atomically. Without a terminal, questions resolve to defaults and the command does not block.

Typical stderr:

```text
detected: rust
written: toven.toml
```

## Print without writing

```bash
toven init --print
```

stdout contains the generated TOML:

```toml
[project]
name = "example"
root = "."
base_ref = "origin/main"

[ecosystems.rust]
manifests = "auto"
```

Diagnostics remain on stderr:

```bash
toven init --print > toven.toml
```

## Non-interactive initialization

```bash
toven init --non-interactive
```

`--non-interactive` selects declared defaults without prompting. It is distinct from release confirmation: authorizing a real release requires `--yes` on `toven release tag/publish`, never `--non-interactive`, so an init habit can never authorize a mutation. Release automation remains opt-in and is not generated by a default non-interactive run.

## Re-run and regenerate

Re-running adds missing ecosystem sections and preserves existing sections, comments, and formatting.

```bash
toven init --force rust
```

`--force` replaces only `[ecosystems.rust]`.

## Detection

The umbrella binary detects linked ecosystems:

- Rust: Cargo manifests and workspaces
- Go: `go.mod` and `go.work`

`manifests = "auto"` and `modules = "auto"` repeat discovery during each plan. Use explicit lists when the managed set must remain fixed.

## Options

| Option | Effect |
|---|---|
| `--root <PATH>` | Inspect another repository root; default `.` |
| `--force <ID>` | Regenerate one ecosystem section |
| `--non-interactive` | Use defaults without prompting |
| `--print` | Write generated TOML to stdout and do not modify the repository |
